# Security policy

Use synthetic data and explicitly authorized resources only. Report suspected vulnerabilities privately using the repository security reporting feature when available, or contact the maintainer without including credentials or sensitive datasets. Provide the affected commit, reproduction and observed impact. Do not publish secrets in issues.

Review authentication, tenant boundaries, independent approval, exact evidence fidelity, replay protection, bounded inputs, file permissions and source-export handling. Production deployment, external provider security and compliance certification are outside this reference implementation. See [the threat model](docs/threat-model.md) for the exact trust assumptions.
